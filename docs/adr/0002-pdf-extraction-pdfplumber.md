# 0002 — PDF text extraction via pdfplumber (replacing pypdf)

## Status

Accepted

## Context

`PdfExtractor` used `pypdf`'s `page.extract_text()`, which reconstructs text
by following the PDF's internal content-stream order. On table-heavy
business documents (payslips, invoices, forms with fixed-position cells —
tested against a real Italian payslip generated by Zucchetti payroll
software) this produced badly garbled output: words split apart with stray
characters inserted between syllables (e.g. "PERIODO DI RETRIBUZIONE" came
out as "PE RIODOsDIsR E TR IBUZIONE"), and separately-positioned table cells
sometimes glued together with no space at all.

## Decision

Switch `PdfExtractor` to `pdfplumber`, which reconstructs text by clustering
each character's actual (x, y) position on the page rather than following
content-stream order. This handles table/form layouts far more reliably.

## Consequences

`pdfplumber` (built on `pdfminer.six`) is a heavier dependency than `pypdf`,
and slightly slower per page — an acceptable trade for correctness on the
kind of real-world documents (payslips, contracts with tables, invoices)
this project explicitly targets. `pypdf` stays in `requirements.txt` only
as a test-fixture builder (`tests/unit/test_pdf_extractor.py` uses
`PdfWriter` to construct a blank-page fixture); it is no longer used by any
production code path.
